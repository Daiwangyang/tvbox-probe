# tvbox-probe

给影视仓用的源筛选器。核心目的只有三条：**一个固定地址、全是能用的快源、换源不丢历史。**

## 先解决你最烦的三个问题

**换配置就丢观看历史**

影视仓的历史记录是跟站点的 `key` 绑定的。网上那些配置的 key 五花八门,
换一份配置就等于全部换了一批陌生人，历史自然对不上。

这里的 key **由接口域名和路径哈希算出**，不带序号：

```
http://abc.com/api.php/provide/vod/   →  s_4358685bfc   (永远是这一个)
```

所以只要这个站还在名单里，不管它排第几、换了 http 还是 https，你上次看到第几集都还在。

**每次都要一个个试**

`python serve.py` 打开面板，每个源的延迟直接列出来，最快的排最上面。
点一次「重测」，几分钟后整份配置自动刷新，投影仪那边**不用改任何设置**。

**只有一个配置地址**

面板顶上给的就是那一个地址。投影仪填一次，之后长期有效。
如果你不想开电脑，把它推到 GitHub，用 Actions 每天定时跑，地址改成
`https://cdn.jsdelivr.net/gh/<你>/tvbox-probe@main/my.json` 也一样，还省得电脑常开。

## 关于广告

网上很多配置里的站是「广告站」：搜到了，点进去却跳到一个第三方解析页，
要求关注公众号、看完贴片才给播。这类站的播放地址不是直链，而是 `jx.xxx.com/?url=`
这种解析地址。

`on_ad_page()` 就是按这个特征判的：抽一条详情页，看播放地址指向哪里。
命中的站降级到最后，并在报告里标「广告解析」。

注意**做不到 100% 干净**。判据是启发式，会漏也会误杀。真正一劳永逸的还是自建媒体库。

## 用法

```bash
python fetch_seeds.py     # 拉种子源(自动走镜像)
python serve.py           # 起面板，浏览器开 127.0.0.1:5678
```

面板上点「重测」，或者命令行直接 `python probe.py`。

产物：

| 文件 | 说明 |
| --- | --- |
| `my.json` | 成品配置，填到影视仓「配置地址」 |
| `report.md` | 人看的报告 |
| `sites.json` | 手工基线，这里面的站优先保留 |
| `quarantine.json` | 淘汰区，记录连续失败次数 |

## 稳定性是怎么保证的

- **基线优先** `sites.json` 里的站是手工挑的，测不通也不会马上删，标记「降级保留」
- **连续淘汰** 一个站要连续 `DROP_AFTER`（默认 2）轮不通才真删，防抖
- **延迟阈值** 超过 `MAX_MS`（默认 1500ms）不进成品，慢的留着也没人点
- **URL 去重** 同一 host+path 的 http/https 合并，只留快的

全挂也不怕：上一次的 `my.json` 会留着，影视仓读到的还是旧的有效配置。

## 加自己的源

编辑 `sites.json` 或 `seeds.txt`，一行一个地址，`#` 后面是备注。

```json
{"sites": [{"name": "我的源", "type": 0, "api": "https://xxx/api.php/provide/vod/"}]}
```

`sites.json` 里的条目会进基线，优先保留。

## 参数

`probe.py` 顶部：`TIMEOUT`、`WORKERS`、`MAX_MS`、`DROP_AFTER`、`MAX_SITES_PER_SOURCE`、`KEYWORDS`。
环境变量 `PROBE_PROXY` 是拉配置用的代理——**测站点固定直连**，因为电视上没有代理，
走代理量出来的延迟不算数。
